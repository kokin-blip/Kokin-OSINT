Focus, contrast, narrow/scaled layout and bounded responsiveness/memory probes pass on Mac; see ../increments/ui-night-ledger-settings-layout.md for scope and measurement limits.

Next: command palette and graph pan/zoom/focus; broader visual regression coverage; manual screen-reader/Windows checks; production cold-start, total-memory and large-case performance gates. Keep focused tests and offline desktop acceptance between changes.

## Sequential, reviewable changes

1. **Audit/baseline:** complete these five documents; record selected image and source limitations, baseline checks, platform gaps and a live screenshot. Keep historical reports and existing working tree changes. Record each phase in a new increment report.
2. **Foundation:** `ui/src/lib/design/` holds semantic CSS tokens, reusable small components, shared motion and licensed local assets. Build a development-only component gallery excluded from release entrypoints. Use the installed Svelte 5 stack; no UI framework/routing/animation dependency. Use the native system-font fallback initially; Inter requires a separate OFL asset-license decision because that license is outside the current allowlist. Bundle only the reviewed MIT outline icons. Dark Night Ledger is the initial default; preserve accessible OS system-font fallback. Light mode follows a verified token/theme implementation in the later settings pass, not an untested toggle.
3. **One vertical slice:** extract the entity dossier presentation from Workbench into `ui/src/lib/features/entities/` while retaining its existing loads/invalidation. Select an entity, read identifiers and supporting/opposing/context evidence, open a relationship or observation, inspect the backend citation verdict, open source bytes and navigate back. Seven confidence dimensions, disagreements, automated actors, explanations and merge attribution remain visible. Reuse existing read components until each is migrated with equivalent behavior.
4. **Shell and core migration:** `ui/src/lib/layout/` provides persistent sidebar, actual case identity, explicitly submitted global search, responsive contextual region and real backend network/operation status. Use Workbench's current sections and entrypoints; expose Graph only with a selected seed and Export through existing operations. Keep import/extract/analytical writes available throughout migration. Migrate evidence/search/activity/export, case gate/recovery/restore and action forms one at a time. Closed/case-changed sessions clear route, pending reads and view preferences containing sensitive IDs. Do not persist case data in browser storage.
5. **Interaction/settings:** keyboard navigation, focus-return, dialogs, collapsible sidebar and user-controlled inspector resizing. Persist only non-sensitive appearance/layout preferences with guarded storage failures. Component gallery covers supported states. Add the palette only for existing commands; no fake recent cases. Accessibility and motion preferences must support OS reduced motion. No unverified feature navigation.
6. **Specialized modules/polish:** preserve bounded graph behavior, add measured pan/zoom/focus and visible truncation; timeline/media/AI/maps/connectors remain disabled until operational contracts exist. Reports use existing package integrity behavior, not a fabricated report engine. Lazy-load graph/gallery/large views and keep pagination; add virtualization only if measured visible page size warrants it.
7. **Validation/release gate:** compare the selected reference and implemented state at equivalent dimensions; record intentional content/API differences. Check typography/layout/colors/assets/copy and fix P0–P2 findings before declaring the redesign complete. Run keyboard, reduced motion, narrow-window/long-identifier checks; deterministic offline desktop acceptance on Mac and Windows; release output must exclude the gallery, synthetic fixtures and desktop driver. Record startup, navigation, memory and frame methodology/results, then changelog and known limitations. Remain unsigned/unnotarized unless separately requested.

## Interfaces, invariants and acceptance

No backend schema or Tauri command change is needed for the foundation/slice. New presentation props accept existing `EntityView`, `SubjectView`, `ObservationView`, `ActivityView` and evidence callbacks; adapters stay in `bindings.ts`. Do not synthesize a total confidence score. Partial coverage remains visible on nonempty searches. Render collected content only as escaped text; no markup injection or automatic outbound links. Operations retain IDs, cancellation and generation-bound rejection; native dialogs stay Rust-owned. Do not load external fonts, imagery, CDNs or telemetry at runtime.

Verify late entity/evidence responses after navigation or unmount cannot populate a different view, source failures are shown without stale quotes, supporting and opposing evidence open their own records, aliases retain provenance, all seven scales appear, and keyboard back/close works. Existing check/test/build are the first gate; affected frontend tests and backend binding/security checks precede desktop automation. Final acceptance repeats the eleven-step investigation workflow, close/reopen/export/restore and preserves identities, lineage and counts.

## Defaults and limitations

Native app behavior takes precedence over decorative mockup details. Case summary counts require existing complete read/coverage APIs; do not count just one paginated page as the whole case. Activity excerpt comes from actual case history and retains the tamper-evident disclaimer. Case-card imagery is a local decorative asset, not evidence. Figma Pro raster previews define composition but grant no reusable component source. No public deployment, PR adoption, backend rewrite, licensing-policy change or new network mechanism is included. Windows verification and hardware measurements require the actual available environment; report unavailable proof candidly.
