# Phase 1 delivery contract

The desktop implementation retains the analyst capabilities in Phase 1 of the approved plan. Source-site platform totals, hosted quotas, internal APIs, automatic searches on typing, aggregate votes, tracking and exact browser UI mechanics are not product requirements. They remain visible in the original inventory and receive an explicit disposition in the feature matrix.

## Delivered scope

- The pinned MIT Framework catalog contains 1,166 entries in 33 top-level branches. List pages contain at most 50 tools. Tree ancestry, search, category breadcrumbs, selected-tool highlighting and a focused details panel provide native navigation. This replaces the website's D3 canvas; it does not claim canvas pan/zoom parity.
- Details expose supplied descriptions, source URLs, pricing, status, inputs, outputs, best use, OPSEC and flags. Missing region/NSFW metadata is explicitly unknown. Source and contribution links open in a browser only on request. Private favorites, half-star ratings, notes and issue drafts live in the unlocked encrypted case. No community rating, issue submission, tracking or update watcher is implied.
- Three independently authored public-profile recipes cover GitHub, Codeberg and Hacker News. This is the actual source count, not the vendors' claimed platform coverage. Reviewed templates, syntax, positive identity fields, negative status/text/null signals, bounded response sizes, redirect refusal and freshness are inspectable. There is no bundled WhatsMyName.io dataset or GPL checker code.
- A case-bound, explicit prepare/authorize/start pipeline produces progressive source results with captured L0 responses and versioned extraction. Each source commits separately. Public fields are shown only when present in the captured response. No verified badge, account ownership or claimability is inferred. Blocked, Unknown, Error, Invalid and Unsupported remain separate; the vocabulary also supports Taken/Available for a future reviewed source that actually establishes them.
- Whole-run source/outcome facets and source/category/outcome filters run before 50-row pagination. Counts and rows use a consistent read transaction. Shredded evidence changes the effective outcome to Unknown before filtering, and cached fields are withheld. Stale asynchronous responses cannot overwrite a newer filter or run.
- Definitive cache reuse authenticates the encrypted source blob. Recipes default to eight hours and can only shorten that ceiling; uncertain answers and provider responses are not reused. The cache key binds the recipe as well as the outgoing request. Copies retain the original observation time. Explicit Rescan bypasses reuse.
- Local suggestions, random handles, case-insensitive username recent-query deduplication, keyboard Enter/Escape, selector focus via /, source favorites and source category filters operate without starting searches. Safe Mode excludes sensitive sources before planning; no sensitive profile recipe is included in this starter set.
- Domain selectors reuse reviewed DNS, RDAP and certificate connectors. Twelve extension shortcuts prepare a new domain query without sending it. Matching RDAP registration events can be displayed; missing DNS/CT data does not establish registration availability. Prices and claim links require the registrar's own browser workflow or a future authorized integration.
- PimEyes, InstantUsername and WhatsMyName proprietary/unsupported coverage remains an explicit browser/import workflow. Handoff sends no query or image. The existing Evidence importer handles a user-selected report or screenshot; the app does not fabricate an automated connector.

## Acceptance

Deterministic tests cover positive, negative, soft-404, challenge, redirected, malformed, oversized and mismatched-identity responses; encrypted evidence and extraction; age ceilings and cache copies; source shredding; whole-run filtering beyond the first page; injection-like filter values; partial results; restore; private review and focus; explicit search and offline controls. The existing 10,000-result projection and full-catalog UI bounds remain in scope.

The macOS receipt and logs are recorded separately in phase-1-validation.json. Live source health is deliberately unverified. Windows runtime, manual VoiceOver and production packaging retain their release gates and are not inferred from macOS fixture acceptance.
