# Phase 2 — selectors, bulk research and hybrid fallback

The Phase 2 selector/bulk slice is implemented for the declared personal desktop scope. Its acceptance receipt is [phase-2-validation.json](phase-2-validation.json). **Phase 3 has not been advanced.** Mixed inventory entries remain partial where their retained investigation/provider clauses belong to Phases 4–5; closing this slice does not establish proprietary service parity.

The user's final hybrid direction supersedes the brief request to replace providers: local processing is the default; optional official APIs remain available for explicitly authorized broader searches. First-party interfaces provide local fallback and special-case handling. They do not reproduce a provider's independent web corpus.

## Delivered native behavior

- Eight selector entry points preserve original spelling and normalized values. Email uses bounded ASCII dot-atom syntax with IDNA domains; quoted/SMTPUTF8 forms receive an explicit unsupported message. Phone inputs require an international prefix. IPv4 rejects shorthand/octal/hex forms; IPv6 is canonicalized. Names/usernames have distinct bounds.
- Ethereum mixed-case inputs require EIP-55. All-lower/all-upper forms retain the no-input-checksum caveat. Bitcoin mainnet Base58Check and witness-aware Bech32/Bech32m, plus TRON Base58Check, validate checksums/payloads. Validation never establishes an account, ownership or balance.
- `research_local_search` is the versioned first-party fallback over the current encrypted case index. It accepts up to 15 validated selectors, returns 50 text leads per query/page with indexing coverage, and records encrypted local query history. The UI mounts one query's page. It opens no socket and needs no credential. Image input receives an explicit unsupported text-search state pointing to the existing media/face workspace; new image search remains Phase 3.
- External sources sit behind an optional disclosure panel. No typing, import, preview, local search or source selection starts an external lookup. Request plans bind selected queries, source requests, image disclosures, budgets, current observation origins and an optional parent import revision. The final consent/start path remains mandatory.
- Public profiles, DNS, RDAP and certificates retain their reviewed brokers. Local SearXNG name/text discovery discloses engine fanout; its app-call ceiling cannot bound upstream engine requests/billing. Wayback CDX uses only the HTTPS domain root, never a pasted path/query/fragment. Snippets and capture indexes remain leads, not collected destination pages.
- CSV, TSV, JSON, text, Markdown and log previews support quoted cells, column suggestions, explicit name joining, mixed-candidate extraction, row errors/type overrides, duplicates, local add/remove and 15-query selection. Text input is bounded to 2 MB/20,000 rows/64 columns. Fifty preview rows are mounted; unselected rows remain available.
- Native window drops accept one regular local file up to 64 MiB. Rust issues a five-minute, single-use, case-bound selection token; the webview receives no path. The analyst separately chooses a bounded text preview or Evidence import. Multiple, oversized, stale-case or consumed selections fail without a search. OS drag gesture itself remains manual release QA; native token handling, frontend event review and real macOS file selection are separately tested.
- The contained PDF/OCR bridge authenticates original bytes and current transformation snapshots outside the case mutex, compares recorded text/kind/locator, and rechecks generation/keys/supersession before publication. Existing limits remain 64 MiB/128 native PDF pages; candidate preview is bounded to 2 MB/10,000 observations and 32 MiB of snapshots. Candidates start unselected. OCR/chunk splits can require manual joining. Unsupported, malformed, missing, stale or shredded sources never become successful empty searches.
- Per-row and single-query image pickers select existing encrypted JPEG/PNG/WEBP references. Picking does not upload. Actual provider image preparation still verifies case ownership, source keys, byte limits and a separate disclosure. Other formats retain explicit existing media limitations.
- Named import workspaces save all reviewed rows in encrypted revisioned `saved_search` documents with purpose `import_session`. They can be resumed, renamed by saving, and archived. Up to 8 MiB of preview metadata is permitted for this subtype; other documents keep 2 MiB. Authorization binds the parent revision and selected rows. Linked run history supplies submitted-query keys and actual source completion separately, including interrupted/partial runs. Reopen and encrypted package/restore preserve them; no request resumes automatically.
- Whole-run filters run before 50-result pagination: source/category/outcome, exact module, scalar field and case-sensitive SQLite GLOB pattern (`*`, `?`, `[]`), verified/private true/false/unknown, reported age and creation/last-seen date ranges. Conditions correlate to one profile. Unknown never becomes false; shredded fields are removed before filtering. Dates describe source calendar dates, not observation/indexing dates.
- Native and typed provider cards retain separate profiles, field origins and normalization recipes. Public names/IDs/followers/location/creation/activity appear only when supplied. Source URLs/images open only explicitly in the external browser; no remote thumbnail fetch occurs. Raw evidence remains expandable and independently inspectable.
- Native profile/RDAP and supported provider account cards can stage account/identifier/relationship review using a current authenticated JSON observation. Account proposals use `social_account`, never an inferred person. Staging writes no L2 conclusion, entity, identifier or relationship.
- Response classification, JSON traversal, native card projection and card-size checks now run before the serialized source commit in production. L0 capture still precedes L1 observation commits. Blob encryption/recording and short SQL writes remain serialized; no claim is made that all evidence I/O is lock-free. The encrypted-disk benchmark records its precise limited scope separately.

## Optional official API contracts

OSINT Industries' documented `spec_format` is normalized as typed assertions, with raw JSON pointers, separate profiles, omission/malformed coverage and unknown-module states. Registration requires a matching query, found module status and typed registered=true. Missing/negative/unknown modules do not establish broad absence. A successful HTTP reply cannot create an identity or breach finding.

The official tutorial explicitly says OSINT Industries does not provide breach data. No HIBP integration is claimed. Account-registration findings and unavailable breach coverage are visibly distinct; separately imported breach reports remain attributed evidence for manual review.

An explicit OSINT Industries credit source makes one authorized fixed GET to `/misc/credits` per batch, transmits no selector/image and reuses the native OI credential. It captures L0/L1 evidence, reports a nonnegative integer balance as available/exhausted, and treats malformed or inaccessible balances as unknown. It never refreshes automatically, reserves credits, or establishes regional/account eligibility. Its image-context selector does not prepare/upload image bytes.

Official search adapters remain optional and **provider-backed, offline-contract tested, live unverified**. Credential presence, usage observations and confirmed eligibility are separate states. Phase 4 retains streaming, additional provider usage/eligibility contracts, page/cost exhaustion behavior and separately authorized live smoke tests. Native keys never enter the UI or packages. No paid call, upload, credential creation or model download was performed for Phase 2 acceptance.

- Phase 4: complete provider gates, stream framing and authorized live coverage/usage/eligibility acceptance.
- Phase 5: graph-board staging/presentation, map/timeline aggregation and richer report/collection workflows. Existing evidence-grounded graph/maps remain available.

Windows runtime, manual VoiceOver/OS drag gestures, remaining dedicated native gates and production release packaging remain honest release gates. They are not described as passed by synthetic fixture coverage.
