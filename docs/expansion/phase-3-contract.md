# Phase 3 — local image preparation and duplicate search

Phase 3 is **in progress**. This continuation implements the bounded local preparation/duplicate slice below. It does not close the phase or imply web-wide image/face coverage. The original 142 inventory entries remain intact in the feature matrix; mixed entries retain their missing clauses.

## Working native behavior

The existing Evidence document inspector now contains Image preparation and local search. Open an image or a processed PDF observation's source document to use it. No query is started by editing fields. Explicit local actions work while the network is offline.

- A versioned recipe supports rectangular crop, clockwise quarter rotations, horizontal/vertical mirror, brightness, contrast and independent RGB offsets. Crop coordinates are source-relative thousandths after EXIF orientation correction; PDFs use the selected native page raster. The contained worker applies orientation, opaque obscuring, crop, rotation, mirroring and color adjustments in that order. It returns a PNG and pHash under existing decoder, memory, time and protocol bounds. Originals remain unchanged.
- Current detected faces on the selected page can be selected, used as crop bounds or opened in the existing local comparison workspace. Obscure other detected faces derives opaque source regions in Rust; it requires a current selected face and refuses too many regions instead of silently dropping them. It cannot guarantee anonymization of undetected faces or other identifying details. Analysts must inspect the saved output. Optional YuNet/SFace resources remain separately installed and reviewed; this change downloads no model.
- Each saved query is a new encrypted image/png artifact with an artifact-to-artifact derivation, versioned L1 transformation, recipe, selected page/face references, engine identity and audit event. It is not a new L0 capture or L2 identity. Further editor changes do not change an already saved query. The same authenticated preview/snapshot representation serves the inspector. The query artifact commits before its separate preview transform; if preview publication fails, committed query evidence is retained and the operation reports the failure.
- Source shredding revokes keys for nested prepared images and their preview/snapshot blobs through append-only schema migration 15. Existing face-index shredding applies to affected image blobs. Search and preview candidates exclude shredded sources. Immutable audit/lineage and legacy pHash metadata remain; this is not a claim to have completed all Phase 6 suppression/removal work.
- A local file picker and native reviewed drop tokens reuse Evidence import. Clipboard paste explicitly captures one PNG/JPEG/WEBP up to 10 MiB as L0 clipboard evidence; it does not infer the originating URL. Image URL collection uses the existing bounded Rust broker with separate destination disclosure and explicit consent, which resets on URL edits. It is disabled offline. Returned content must be inspected; a URL is not proof of an image response. The webview fetches no remote pixels or thumbnails.
- Exact duplicate search compares captured whole-file content hashes, including PDF bytes. Perceptual search compares the stored pHash of processed images/pages at a bit distance selected from 0–16 (default 8). Unprocessed images/pages are not silently searched by an on-demand inference job. The selected query source and pHash snapshot are authenticated before processing; candidate fingerprints are stored L1 signals and the candidate must be inspected for current integrity. Results never establish identity, confidence, authenticity or location.
- Search is case-scoped and returns at most 50 candidates per page. Real scan budgets are 500, 5,000 (default) or 20,000 indexed records, with a 32 MiB metadata projection ceiling. Candidates are selected newest-first before filtering/sorting; truncated scans and counts are disclosed. The entire query artifact is excluded, including other pages of the same PDF. Read-only comparison/authentication runs outside the case lock; generation and result key availability are checked before publication. Preparation uses the existing cancellable, single-native-task scheduler.
- Filters cover exact known source domain, known page-title substring, indexing date range and captured file byte size. Missing domain/title cannot match a corresponding filter. Artifact creation time is labeled separately from index time; it is not relabeled as an L0 capture date. Publication date and language are explicitly unknown. The size filter is file bytes, not decoded pixel dimensions. Best/worst pHash distance, newest/oldest indexed and round-robin domain diversity sort the bounded matches. Domain counts group available metadata; this does not yet coalesce identical images with all hosting URLs.
- Inspecting a candidate opens its evidence and correct page. A saved query ID can be copied and a saved prepared image can be selected for the next explicit search. There is no public sharing URL, background scan, automatic identity link or provider request.

## Native interfaces and privacy boundaries

`image_query_info` and `image_query_search` are typed case-generation-bound Tauri commands. `image_prepare` and `image_clipboard_import` are existing-scheduler operations. This is a first-party in-process API, not a listening HTTP service. Commands and workers have no new network transport. Official providers remain optional under the separate reviewed plan, Keychain and budget paths; no fallback silently uploads a query. Image, text and existing face indexes remain separate.

No dependency, model, native license exception, purchase or provider credential is added. Raster formats remain reviewed JPEG/PNG/WEBP/TIFF; PDF preparation reuses PDFium. Clipboard has its narrower reviewed formats/size. File/worker input is bounded to 64 MiB, raster decode to 16 million pixels, and serialized worker output to 16 MiB; oversized or corrupt content fails visibly.
